feat/go-backend · local M1

Go 接手控制面，
Agent 仍然跑在官方运行时里。

这次改造不是“把 Agent 重写成 Go”。Go 只替换 FastAPI 那一层：鉴权前的 HTTP 入口、SSE 封装、请求生命周期和 dsh 子进程管理。 真正的模型循环、工具调用和 website-tools.mjs 仍然由官方 Node 运行时执行。

Go 控制面 / SSE / 进程管理 Node dsh 官方 Agent 运行时 Next.js 会话 / CSRF / 代理 Python 保留为对照与回滚
01 · First look

一句话看懂分工

三条链路各管一件事：浏览器不直接碰模型，Go 不重写 Agent，Node 不处理公网会话。

Go

Go 负责“稳定地把请求送到运行时”

HTTP 路由、请求体限制、SSE 帧、取消传播、每请求 runtime 租约、进程组回收、日志与 readiness。

dsh

官方运行时负责“真正调用模型和工具”

DeepSeek Harness 的 Node 单文件程序继续执行模型循环，加载 sdk-minimal profile、站点 patch 和受限工具。

Next

Next.js 继续守住浏览器边界

签名会话、CSRF、同源校验、客户端 IP 规范化、关系内容 Cookie 和 /api/chat 代理都没有搬走。

关键结论：Go 版本仍然需要 Node 运行时和 website-tools.mjs。它没有把 267MB 的 dsh 变成 Go，也没有改变模型调用成本；改变的是控制面的语言、进程模型和部署方式。

03 · Request walkthrough

一次 v2 聊天请求发生了什么

时间从上到下。真正昂贵的模型循环在 dsh 内；Go 负责把它的通知变成浏览器能消费的 SSE。

为什么有两个“最终”：dsh 的增量文本可能包含工具前言或中间草稿；Go 只把流式 delta 当作预览，真正的最终答案以 assistant/message 为准，最后一条 reply final 会覆盖所有临时文本。
04 · Protocol v2

v2 SSE 事件生命周期

当前前端默认走 v2。事件顺序是固定的：进度 → 工具 → 增量 → 最终 → 可选桌面事件 → done。

01
准备运行时 Go 先告诉浏览器要开始准备了，然后才获取租约、启动 dsh。 data: {"event":"progress","stage":"preparing","message":"正在准备站内助手…"}
02
分析问题 真实推理内容不会下发；只映射成固定状态。 data: {"event":"progress","stage":"analyzing","message":"正在分析问题…"}
03
工具状态 工具事件来自真实 tool/call 和 tool/result，不是模型自己声称。 data: {"event":"tool","name":"desktop_apps","status":"running","message":"正在查询站内内容…"}
04
增量文本 同一 message_id 下的 delta 可以合并；最终会被 final 覆盖。 data: {"event":"reply","phase":"delta","message_id":"reply-…","content":"My World 的"}
05
最终答案 来自根会话最后一条 assistant/message，UTF-8 字节上限受控。 data: {"event":"reply","phase":"final","message_id":"reply-…","content":"完整答案"}
06
可选的桌面解锁 只有五题验证真实通过且整轮完成，才在 final 之后发送；proof 由后端 HMAC 签发。 data: {"event":"desktop","action":"unlock-girlfriend","proof":"v1.…"}
07
完成 只有收到正常 done，前端才认定整轮成功。 data: {"done":true}
05 · Cancellation

取消与进程回收原理

这是这套代码最关键的安全边界：浏览器断开不能留下一个还在跑的模型进程。

1浏览器断开用户点停止、关闭页面或网络中断。
2Next 取消上游代理 AbortController 触发，切断到 Go 的请求。
3Go context 取消请求 context done，Stream 停止读缓冲。
4Worker 退出Harness 的阻塞调用被取消，不再发布事件。
5关闭 dshshutdown → 关 stdin → TERM 进程组 → 必要时 KILL。
6不补发 done日志记录 cancelled，pgrep 查不到残留 dsh。

取消发生在等待阶段

尚未拿到执行名额时直接退出，不扣额度、不启动 runtime。

取消发生在执行阶段

已开始的模型调用仍会关闭子进程；不会把失败包装成成功，也不会补发 done。

06 · Code map

代码地图

新增代码全部在 backend-go/；没有改 Python、前端和 Agent 资产。

cmd/neko-backend/

入口、配置加载、HTTP server、信号与优雅关闭。

internal/api

路由、CORS、请求体限制、JSON/SSE 输出、错误映射、request ID。

internal/agent

Service、Runtime Manager、ProgressiveReply、有界 StreamBuffer、工具事件与桌面解锁判定。

internal/harness

stdio JSON-RPC 客户端、通知队列、会话树、stderr 环形缓冲、进程组关闭。

internal/chat

消息结构与严格校验；字符数用 rune，回复上限用 byte。

internal/config

环境变量、.env、CORS、DSH 路径自动发现、参数校验。

internal/relationship

2 分钟有效的解锁 HMAC proof。

internal/observability

JSON 日志、request ID、状态码与耗时统计；不记录正文/密钥/IP。

07 · Boundaries

当前边界：什么已经跑通，什么还没做

这是本地 M1，不是生产替换。生产级准入、配额和部署仍留给下一阶段。

  • ✓Go 直连真实 dsh，非流式回复成功
  • ✓旧版 SSE 与 v2 SSE 都可用
  • ✓工具状态事件、最终文本、桌面 proof 判定
  • ✓取消后 dsh 进程组被回收
  • ✓Next 代理指向 Go 后聊天正常
  • ✓go test ./... -race 与 go vet 通过
  • ○生产 FIFO 准入、AttemptGuard、SQLite 配额
  • ○systemd、Docker、dsh 二进制分发与校验
  • ○完整彩蛋浏览器流程与 Python/Go 差分测试
  • ○Postgres 可选层（当前没有实际业务表）
08 · Run it

本地怎么跑

Go 工具链当前在忽略提交的 work/toolchain，不会污染系统 PATH。

export PATH="$PWD/work/toolchain/go/bin:$PATH"

cd backend-go
NEKO_ENV_FILE=../backend/.env \
NEKO_ROOT=.. \
PORT=8011 \
ENVIRONMENT=development \
go run ./cmd/neko-backend

# 另一个终端：前端指向 Go
cd frontend
PYTHON_API_URL=http://127.0.0.1:8011 \
NEXT_PUBLIC_APP_URL=http://127.0.0.1:3011 \
npm run dev -- --hostname 127.0.0.1 --port 3011
当前实测地址：Go http://127.0.0.1:8011，Next http://127.0.0.1:3011。 日志在 work/nekovccat-go.log 与 work/nekovccat-go-frontend.log。
